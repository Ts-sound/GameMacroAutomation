# 需求文档

## 项目概述

**项目名称：** 游戏宏自动化
**类型：** 桌面自动化工具
**平台：** 仅 Windows
**核心价值：** 录制鼠标键盘操作 → 生成脚本 → 通过图像识别自动执行

## 功能需求

### FR1: 脚本录制

- **FR1.1** 用户可以选择游戏窗口进行录制
- **FR1.2** 系统捕获鼠标点击事件并记录坐标
- **FR1.3** 系统捕获键盘按键事件
- **FR1.4** 系统在每次点击时截取屏幕截图
- **FR1.5** 用户可以通过 F12 热键停止录制
- **FR1.6** 系统生成包含动作和截图的 YAML 脚本

### FR2: 脚本执行

- **FR2.1** 系统可以执行录制的 YAML 脚本
- **FR2.2** 可以使用 Python 脚本处理复杂逻辑
- **FR2.3** 系统支持基于图像的点击（模板匹配）
- **FR2.4** 系统支持基于坐标的点击作为备用方案
- **FR2.5** 用户可以在运行时指定目标窗口

### FR3: 图像识别

- **FR3.1** 系统可以使用 pyautogui 在屏幕上定位图像
- **FR3.2** 用户可以配置置信度阈值（默认 0.8）
- **FR3.3** 系统支持带超时的 wait_image
- **FR3.4** 系统支持 image_exists 检查

### FR4: 循环控制

- **FR4.1** 系统支持 loop_while（条件循环）
- **FR4.2** 系统支持 loop_times（固定次数循环）
- **FR4.3** 系统支持 loop_until（直到满足条件）
- **FR4.4** 所有循环支持 max_iterations 防止无限循环

### FR5: 脚本管理

- **FR5.1** 系统在执行前验证 YAML 脚本
- **FR5.2** 系统检查资源的文件是否存在
- **FR5.3** 系统显示脚本依赖树
- **FR5.4** 系统支持子脚本调用

### FR6: 日志

- **FR6.1** 系统支持可配置的日志级别（DEBUG/INFO/WARNING/ERROR）
- **FR6.2** 系统生成执行报告
- **FR6.3** 日志同时输出到控制台和文件

### FR7: 区域截图

- **FR7.1** 系统可以截取指定区域的屏幕截图
- **FR7.2** 用户可以捕获检测区域图像用于图像识别

## 非功能需求

### NFR1: 性能

- **NFR1.1** 图像匹配应在 2 秒内完成
- **NFR1.2** 脚本执行在空闲时不应超过 10% CPU 使用率

### NFR2: 兼容性

- **NFR2.1** 支持 Windows 10/11
- **NFR2.2** 支持 1920x1080 和 1280x720 分辨率
- **NFR2.3** 自动检测并应用不同分辨率的缩放因子

### NFR3: 可靠性

- **NFR3.1** 脚本执行应优雅处理图像未找到的情况
- **NFR3.2** 系统应在失败时重试（可配置）
- **NFR3.3** 提供详细的错误日志用于调试

## 用户故事

| ID | 故事 | 优先级 |
|----|------|--------|
| US1 | 作为一个玩家，我想录制我的技能连招以便自动重复播放 | 必须 |
| US2 | 作为一个玩家，我想使用图像识别来确保点击准确 | 必须 |
| US3 | 作为一个用户，我想编写 Python 脚本进行复杂自动化 | 必须 |
| US4 | 作为一个用户，我想使用循环和条件实现灵活自动化 | 必须 |
| US5 | 作为一个用户，我想调用子脚本实现模块化自动化 | 应该 |
| US6 | 作为一个用户，我想查看执行报告用于调试 | 应该 |
